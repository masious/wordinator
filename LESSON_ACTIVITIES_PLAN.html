01 · Settled scope

Read a sectionChoose an activityOpen its own pageReuse or generate contentReturn to the section
  • Suggestions appear in the existing Do more with AI area and change with the active section. No inline activity insertion is required.
  • Opening an activity navigates in the same browser tab to a new application page. A link at the top returns to the source lesson and section.
  • Ship seven activity types: story summary, story comprehension, grammar explanation, quick grammar question, tricky grammar practice, lesson-wide mixed practice, and original-dialogue role-play.
  • Attach and suggest are one operation: an eligible activity is associated with its source and offered there, including before any user has generated its content.
  • One shared cached activity per source section and type, for the current source and recipe versions. No variants, “generate another,” ratings, or content-management interface in this release.
  • Generation starts only when someone opens the activity. Source changes invalidate affected content. Learner answers and completion stay private and do not affect required lesson completion.
  • Role-play replays the original dialogue. The learner is Sofia; the app voices all other characters. Learners choose English cues or exact Dutch lines, hold the microphone button to speak, and explicitly send their turn. Typing is always available.
Excluded: vocabulary activities or grouping, weak-word practice, personalization, cross-lesson retrieval, two-lesson checkpoints, older vocabulary, Tutor conversations, live generated dialogue, and changes to existing Tutor-saved practices. Words already present in source sentences remain ordinary lesson content; no vocabulary index or word-memory reads/writes are introduced.

Engineering defaults: fixed activity sizes below, finite exercises rather than a chat, no author approval before caching a schema-valid result, private resumable work, existing provider fallback and speech infrastructure, and deterministic suggestion eligibility. These are implementation choices within the agreed scope, not additional claimed user requirements.

03 · Resolve sections once, consistently

The existing index follows level-1/2 headings through LessonIndex.tsx; its overview also understands level-3 stops. Activities need the small grammar sections as well. Extract a deterministic shared section/source resolver into packages/contracts/src/lessonActivities.ts, with no DOM or server dependencies.

  1. Use stable published block IDs. A content-bearing top-level heading starts a section until the next heading of equal or higher level. Level-3 grammar subsections are eligible independently; nested column headings stay within their top-level section.
  2. Create a synthetic introduction source for meaningful blocks before the first heading and a synthetic lesson-end source for whole-lesson mixed practice. Empty headings alone do not produce activities.
  3. Classify from structured lesson content and the existing overview conventions, not a model call while scrolling. Dialogue sections offer story activities. Grammar callouts/recognized grammar sections offer grammar activities. Summary sections and the final lesson endpoint offer mixed practice. Unsupported sections offer no contextual activity.
  4. A story section with several dialogues offers role-play links labelled by dialogue; each dialogue ID is a distinct role-play source. Offer role-play only for dialogues with a case-insensitive, trimmed Sofia speaker and at least one partner turn. Never silently rename another character to Sofia.
  5. Use the reading line to resolve the current fine-grained section. Reuse the existing measurement approach; keep index highlighting at its current coarser level. Scrolling backward changes suggestions back. A short final section becomes current at page bottom.
  6. Before the start gate is passed, in draft previews, and for unpublished lessons, show no new activity suggestions. At lesson top, use an eligible introduction or no suggestions; do not guess a later section. On a finished lesson, suggestions still follow the current viewport.

Every suggestion carries a stable type, source ID, source label, return heading/block ID, and source fingerprint. Suggestions are computed without content generation and without learner history. The API derives and checks them again rather than trusting browser-supplied block text or eligibility.

Placement: replace the two generic lesson-wide AI prompt links within Do more with AI with these contextual activity links. Keep Practise words as an ordinary lesson utility outside this activity list, with its existing behavior. Keep the Tutor navigation destination and existing AI-practice expander unchanged. Use the current footer/drawer placements on narrow screens; do not introduce a second mobile suggestion surface.

04 · Role-play interaction contract

The full original dialogue fixes turn order and reference lines. English cues come from stored translations where available; missing cues are generated once and cached without rewriting Dutch lines. Exact Dutch mode and English mode share the same activity and can be switched during a turn.

  1. The activity opens with a visible source title, top return link, cue-language switch, and a Start dialogue control. The explicit start permits partner audio playback; never autoplay before a user gesture.
  2. Play consecutive partner turns in the course’s cast voices, in original order, stopping before Sofia’s turn. Display partner text and provide replay. If Sofia opens the scene, begin with her cue.
  3. On Sofia’s turn, show either her English cue or her exact Dutch sentence. In English mode, Reveal Dutch is available. Keep a typed answer field and an always-visible, ready-to-use hold-to-speak button.
  4. Pointer down starts capture; pointer release ends the utterance and places the final transcription in an editable draft. Repeated holds may replace that unsent utterance, with an explicit visible draft. Holding Space/Enter while the microphone button is focused provides equivalent keyboard behavior. Ignore repeated keydown events.
  5. Releasing the microphone does not send or advance. Send submits the current spoken transcript or typed answer. Disable it for empty drafts, while recognition is finalizing, and during an in-flight submission. Use an idempotency key so double clicks do not create extra attempts.
  6. Show feedback against Sofia’s original line, plus pronunciation feedback when available. Offer Retry and Listen to Sofia. An explicit Continue action plays the next partner turn; do not start it behind feedback. The final turn instead offers Finish and Back to lesson.
“Microphone ready all the time” means the control stays visible and the recognition client/token can be prepared after permission. It does not mean continuous recording. Capture runs only while held, never during partner playback. Stop and release capture on pointer cancellation, lost focus, route change, sign-out, and hidden tab. If permission or recognition fails, typing remains usable.

Feedback default: this is reproduction of the lesson’s line, in either cue mode. Normalize case, whitespace, punctuation, and the project’s existing accent equivalence for sentence comparison; do not reuse word-card matching that strips leading articles. A different sentence is labelled “Different from Sofia’s line,” with the original shown; it is not automatically called bad Dutch. No open-ended semantic judge is needed for this release. Retrying or continuing is never blocked by a mismatch or a low pronunciation score.

Microsoft recognition may assess pronunciation against the original line. Browser recognition and typing have no pronunciation score; do not fabricate one. Show reference-based pronunciation as feedback on repeating that specific sentence. Long dialogue lines must have explicit sentence/chunk handling within provider and contract limits; never truncate a reference silently. Keep a chunk position inside the Sofia turn and require Send for the complete turn.

Audio stays between the browser and the configured recognizer; never store raw learner audio. Sending a spoken answer explicitly sends its editable transcription as private activity answer text. This is a documented extension of the current speech privacy rules, which otherwise say transcripts are not sent. Generated partner speech is public-by-URL under the existing R2 convention, contains only original lesson text, and uses cast voices rather than the narrator-only Tutor audio default.

05 · Shared content, private work

Cache identity: lesson ID + source ID + activity type + source hash + recipe version + output-schema version + language. For role-play, source ID includes the dialogue block ID. Cue mode and learner ID are not cache dimensions. Use stable serialization and a cryptographic hash.

  • The source hash includes the actual published text, relevant headings, dialogue/translation data, and the lesson goal when used by the recipe. Mixed practice hashes the whole allowed lesson source. Exclude standalone vocabulary blocks, private notes, author identity, learner data, and progress. Do not invalidate a grammar exercise merely because an unrelated story changed.
  • Role-play text and cues invalidate on dialogue changes. Voice/cast changes invalidate the corresponding audio identity, while keeping unchanged cue content reusable.
  • Database rows have pending, ready, or failed state. A unique cache key and a conditional, expiring generation lease elect one generator; simultaneous visitors poll the same row. A stale owner may never overwrite a newer lease.
  • After claiming, run bounded generation through the existing configured AI provider layer and fallback. Treat lesson text as data; no tools, learner profile, Tutor snapshot, or user-supplied system prompt. Validate output strictly before atomically marking ready.
  • Recheck source identity before committing. A republish during generation leaves the result stale and unavailable to new launches. Do not serve an old version under the new source key.
  • Waiting clients poll using the server’s retry hint, with a bounded visible wait and Retry after a timeout. Failed generation can be retried after a short server backoff under the same identity; retries are recovery, not new variants. Cancelled browser navigation does not delete another visitor’s job.
  • Role-play with complete existing translations can be materialized deterministically without a model call; audio may still load independently. Content-ready does not imply every audio clip is ready.
  • Cache hits remain usable when AI generation is unavailable or the opener has exhausted the generation allowance. Reference grading stays available. Audio remains subject to existing speech availability and caps.

Published content changes invalidate by key rather than destructive replacement. An already-open run may finish against its immutable version while the lesson remains readable, with a source-updated notice. New runs always resolve current source content. Retain stale rows only while referenced by private runs; purge unreferenced stale rows through the maintenance path. Deleting a lesson deletes its activities and private runs; unpublishing immediately blocks learner access.

Metering default: count one cache-miss model generation as one existing daily AI turn for the requesting account, without creating a Tutor conversation; cache hits and deterministic role-play materialization count zero. Fallback attempts count once. Reserve allowance when taking the lease, with concurrency-safe checks, rather than relying only on a pre-request count. Speech uses existing accounting with a new activity surface. No separate user-facing quota setting is introduced.

06 · Contracts, persistence and endpoints

Keep one source of shared types in @wordinator/contracts, with a new lesson-activities subpath. Reuse appropriate answer views, pure graders, recognition and playback primitives; do not route these activities through Tutor messages, tools, or conversations.

Extend lesson reset to delete this learner’s activity runs/answers while preserving shared activity content. Lesson deletion cascades both shared and private activity records.

Proposed global routes (under /api/courses/:courseId/lessons/:lessonId; do not add new group-shaped contracts):

  • GET /activities — deterministic eligible source/type descriptors, never generation and never private payloads.
  • POST /activities/open — accepts source ID, type, and expected source fingerprint; resolves current published content, reuses/claims cache, and returns ready activity + own run or 202 with a poll URL. 409 SOURCE_CHANGED asks the client to refresh.
  • GET /activities/:activityId — rechecks access; returns generation status or a reference-stripped activity view plus this account’s run. Stale versions are readable only through an existing owned run.
  • POST /activities/:activityId/answers — owned run ID, item/turn ID, answer, input mode, optional validated assessment, and idempotency key. Server grades from stored payload, returns private feedback, and never trusts a browser’s verdict. Client pronunciation scores remain unverified learning feedback, not authorization.
  • PATCH /activities/:activityId/run — narrow validated actions: change cue mode, continue, complete, restart. The server validates legal item/turn transitions and completion conditions.
  • POST /activities/:activityId/speech — accepts a stored turn/chunk ID only; resolves original text and cast voice server-side, applies speech caps, and returns ready/pending audio. Never accept arbitrary synthesis text or voice.

All routes require authentication, completed username setup, and current lesson visibility. Verify course/lesson/activity/run/item ownership at every step. A readable archived lesson may serve ready content and audio but cannot create shared content or persist new learner work; use an ephemeral read-only practice run and make its unsaved state clear. Draft preview is excluded even for editors.

Page route: /courses/$courseSlug/lessons/$lessonSlug/activities/$sourceId/$activityType. Route loader ensures lesson and descriptor only; Query owns cache status, run, and mutations. Loading/opening is idempotent. Direct links resolve through the same open flow. Back to lesson uses the canonical current lesson URL and original heading/block anchor, falling back to lesson top if that anchor was removed.

Drafts: unsent text is device-local and namespaced by account, activity version, run, item, and schema version. Preserve it on sign-out without exposing it to another account. On source change, do not silently apply old drafts to new questions. Refresh resumes submitted work from the server.

07 · Page states and learning-time boundary

  • Use the normal authenticated frame, a compact source header with the top return link, one primary activity column, and a progress indicator for question/turn position. This is an activity page, not a Tutor conversation with a composer.
  • Support preparing, shared generation pending, ready, checking, feedback, finished, failed/retry, source changed, source unavailable, and archived/unsaved states. Errors retain the return link and local draft.
  • Use Mantine, CSS Modules, existing Lumen tokens and shared UI; all visible product copy is behind i18next keys. Phone layout preserves the cue switch, microphone, typing, Send, and return link without overflow. Reduced motion disables decorative transitions.
  • Retain a keyboard path through every question and role-play action. Announce recognition and generation status without stealing focus; hold-to-talk must also work with touch and keyboard. Explicit user gestures govern audio, recording and advancement.
  • Extend the existing learning clock with lesson_activity and reading/grammar/speaking focus. Attribute time to lesson + activity, pause for hidden/idle states and generation waits, and prevent double counting with lesson reading or Tutor time. Add this category to existing totals/daily goal; do not fold it into required practice or typical lesson-reading medians.

# Design system

Wordinator’s interface is a focused learning workspace: calm, compact, and editorially clear. It balances readable lesson prose with the density of a capable study tool, and it should never feel like a competitive learning dashboard.

This file owns canonical design values. Define these as CSS custom properties and map applicable values into the Mantine theme. Components must consume semantic tokens rather than repeat raw values. Changing a token requires updating this document.

## Approved visual direction

The approved direction is **Lumen** (adopted 2026-10-16): a cool off-white canvas, white paper surfaces, near-black ink, one violet accent, soft blue, lime, and warm tints for categories and states, Inter throughout with tightly tracked headings, small radii, single-layer cards with a line border and a soft shadow, and a persistent left navigation rail. Reference compositions are the course library (page header, a dark continue-learning feature panel, and a three-column course grid), the lesson reader (lesson rail, reading column, and a tabbed reference panel), and the tutor (chat with avatar turns, a floating composer, and a context panel).

The Lumen token layer and the shared components are shipped: every semantic role carries Lumen values, Inter replaces Manrope and Newsreader, and the exports in `apps/web/src/ui` plus `ProgressMeter` and `Callout` follow the [component character](#component-character) below. The application shell (left rail) is shipped too; page families migrate through [REDESIGN_PLAN.md](../REDESIGN_PLAN.md). Until a page's batch lands, the shell and page rules in the list below describe the shipped Editorial Luxury structure (page-local pills and bezels) rendered with Lumen values; each batch rewrites the rules it replaces.

Wordinator continues to use Mantine and CSS Modules; Tailwind is prohibited. Plain-text content (course lessons excepted, see [courses](courses.md#lesson-documents)), accessible focus treatment, and reduced-motion behavior take precedence over the reference compositions.

The previous Editorial Luxury refresh was delivered through the visual redesign plan (`VISUAL-REDESIGN-PLAN.md`, removed in `938d46c`; see git history). Its shell and page rules that are still shipped follow:

- Inter Variable is the self-hosted family for interface, authored text, and headings; the display role is Inter with `--tracking-display`.
- Page and section rhythm grows substantially on wide screens. Desktop is the design target for new work (see [responsive behavior](#responsive-behavior)).
- Entry, overlay, hover, and press motion uses centralized custom cubic-bezier curves and only animates `transform` and `opacity`.
- Backdrop blur is limited to overlays. The paper grain layer and page glows were removed with the Lumen shell.
- **Application shell** (Lumen, 2026-10-16): every authenticated route renders in a product frame — a sticky, full-height left rail (`--size-app-rail`, `--color-surface-raised`, a right line border) beside the content column on `--color-surface`. The rail holds the brand (the 2×2 mark on `--color-inverse-surface` with one tall accent tile, rotated `-4deg`, and the Wordinator name), the Main navigation, and a footer profile row (soft avatar, name, `@username`, and an Account menu button with Settings and Sign out in `--color-danger-text`). Navigation items, in order: Courses, Words, Journal, Tutor — each a line icon and label at `--type-control-label` semibold, `--radius-sm`, with hover and `aria-current="page"` on `--color-action-soft`. Notices is an on-demand supporting destination linked from Settings rather than the main rail. Under Courses, every course the viewer can see is listed in library order as indented sub-items on a line rule (`--text-xs`; the current course on the soft accent); navigation items and sub-items run to the rail's border with only their start corners rounded; a title wider than the rail fades out at its end and, while its item is hovered or keyboard-focused, slides at a steady pace to reveal the rest (no slide under reduced motion; the full title is the item's tooltip); a disclosure button at the end of the Courses item collapses the list. On course and lesson pages (`/courses` and below) the list is expanded by default and the choice is remembered per account and device in `localStorage`; on every other page it starts collapsed, and expanding it there is not remembered (changed 2026-10-16). On a lesson page with the list expanded, Courses is promoted to a heading (`--text-md` bold in `--color-foreground`, a `1.25rem` icon, no soft fill unless hovered) and the other items become one row of equal icon links above the lesson box (`--control-height`, `--radius-sm`, a hairline top rule, hover and current on `--color-action-soft`, a Mantine tooltip with the label; the row is a navigation landmark labelled More navigation). The lesson index's entries keep to one line with an ellipsis and carry their label as a tooltip; the lesson box puts Practise words and Ask AI on one two-column row above Ask for more practices like this, and its Fluency block lists Words remembered well, Pronunciation fluency, and Last studied. The rail's right edge is a resize handle (a vertical separator, `col-resize`, an accent line on hover, focus, or drag): dragging it, or the arrow keys (16px steps, Home and End for the bounds), set the rail between 200px and 400px, and a double click or Escape restores `--size-app-rail`; the width overrides `--size-app-rail` on the shell (so `--shell-inline-start` follows) and is remembered per account and device in `localStorage`. The drawer keeps the default width. The content column sets `--shell-inline-start` (and, with the lesson page's right rail, `--shell-inline-end`) so window-fixed bars (the lesson progress bar) start and end at its edges.
- Below `68rem` the rail is hidden and a sticky slim header (`--navigation-height`, paper, bottom line border) shows an Open navigation button, the brand, and the account avatar (the same Account menu). The button opens the rail's contents in a Mantine drawer (`--size-app-rail` wide, labelled Main navigation), which closes on navigation. The phone dock and More sheet are retired. The rail's lesson slots (index and lesson box) move into the drawer at this width.
- Authentication and invitation routes use an editorial split above `48em` and a direct single-column composition below it. Supporting authenticated pages use asymmetric identity, settings, and directory compositions on wide screens, collapse to one column on narrow screens, and keep notifications as quiet separated rows rather than independent elevated cards ([Journal](#journal)).
- Destructive membership and group-lifecycle operations use the shared adaptive confirmation dialog. Native browser confirmation is not part of the application interaction language.

## Token architecture

Primitive tokens are fixed visual ingredients and use the `--palette-*` namespace. Semantic tokens describe a role, such as `--color-page`, `--color-action`, `--color-danger-surface`, or `--color-focus`. Application and reusable-component styles consume semantic roles; primitives are used only to define those roles or to document the palette in `/ui`.

Typography, spacing, radii, shadows, motion, content widths, control heights, minimum touch targets, breakpoints, and layer order are centralized alongside color in `tokens.css`. Mantine maps applicable theme fields back to these custom properties instead of maintaining a second independent set of values. Explicit component props may override theme defaults when a feature has a documented reason.

Surface roles include `--color-bezel`, `--color-core`, `--color-hairline`, `--color-inner-highlight`, `--color-separator`, `--color-navigation-glass`, `--color-overlay`, and `--color-overlay-glass`. State roles include hover, active, disabled, unread, selected, concealed, and pinned. The former paper, ink, mint, yellow, and blue compatibility aliases were removed with the Lumen palette; component code uses semantic roles.

Accent colors should usually appear as backgrounds paired with the scheme's high-contrast foreground, not as low-contrast body text. Dark mode remaps the same semantic roles instead of adding page-specific branches. Its charcoal canvas, lifted surfaces, near-white text, restrained tints, solid line borders, and black diffuse shadows preserve the light theme's hierarchy without pure-black expanses. Body, muted, action, danger, selected, and focus pairs are browser-tested in both schemes; their audited contrast ratios meet the applicable `4.5:1` text or `3:1` focus threshold.

`--color-action-text` is white for accent surfaces in both schemes; text on any other surface uses `--color-foreground`, including hover emphasis on transparent icon and text buttons. Shared buttons pair each variant's surface with its ink through `--button-surface` and `--button-ink`: primary sits on `--color-action` (`--color-hover` while hovered), secondary on `--color-control-surface` (white in light, a lifted `#2A2B31` in dark so the control separates from cards), quiet is transparent with `--color-foreground`, danger keeps `--color-danger-surface` and `--color-danger-text`, and the icon button sits on `--color-highlight-soft`. Where the browser supports CSS `contrast-color()`, primary, secondary, and icon-button ink is derived from the surface (the black or white it returns, mixed 12% toward the surface to stay warm); the token ink is the fallback. Hover and press keep the variant's own surface and ink rather than Mantine's filled hover colors; a quiet button gains a `--color-wash-strong` wash. Rendered buttons, at rest and hovered, are browser-tested in both schemes against what is painted behind them.

## Theme preference contract

Theme preference is browser-local and intentionally independent of accounts, groups, the API, and the database. The storage key is `wordinator:color-scheme`; explicit values are `light` and `dark`, while a missing value or Mantine's internal `auto` value means the user-facing `system` preference. System is the default and continues to respond to `prefers-color-scheme` changes.

The inline head bootstrap resolves the scheme before first paint and sets `data-mantine-color-scheme`, the document `color-scheme`, and `<meta name="theme-color">`. Mantine's local-storage manager owns subsequent preference updates, and the runtime synchronizer keeps browser chrome metadata aligned with the resolved scheme. The shared labelled segmented control appears in Settings at desktop and mobile sizes and in `/ui`; its text state remains understandable without icon interpretation. Global styles never filter or dim uploaded images, avatars, or group icons.

## Typography

Self-host font assets where licensing permits; do not add a tracking font CDN.

| Token | Stack | Use |
| --- | --- | --- |
| `--font-sans` | `"Inter Variable", Inter, ui-sans-serif, system-ui, sans-serif` | UI, authored content, and headings |
| `--font-display` / `--font-serif` | aliases of `--font-sans` | Display, page, and section headings (tight tracking); kept as names while components migrate |
| `--font-mono` | `"DM Mono", ui-monospace, monospace` | Labels, post types, practice eyebrows, counters, compact metadata, `<kbd>` (kept in Lumen) |

Inter and DM Mono are distributed under the SIL Open Font License 1.1. The web package self-hosts their Fontsource assets (`@fontsource-variable/inter` normal and italic) with `font-display: swap`; no font request is made to a tracking CDN and primary typography does not depend on fonts installed on the user's device.

The base scale runs from `0.75rem` through `3rem`. Semantic roles are `--text-display` (`clamp(2.3rem, 4vw, 4.1rem)`, the lesson title), `--type-page-title` (`clamp(2rem, 3vw, 3.25rem)`), `--type-section-title` (`clamp(1.15rem, 1.4vw, 1.45rem)`), `--type-card-title` (`1rem`), `--type-body` (`0.875rem`), `--type-authored` (`0.97rem`), `--type-metadata` (`0.75rem`), `--type-eyebrow` (`0.7rem`), and `--type-control-label` (`0.8125rem`). Weights are `400`, `500`, `600`, and `700`. Body line height is `1.6`, lesson prose uses `--line-reading` (`1.85`), compact labels use `1.25`, headings `1.05`, and titles `1.3`. Display and page titles track at `--tracking-display` (`-0.055em`), section and card titles at `--tracking-title` (`-0.035em`). Eyebrows are uppercase at `--tracking-eyebrow` (`0.1em`); avoid other long all-caps text.

Posts have their own roles so every post kind reads the same: `--type-post-author` (`0.875rem`, sans, semibold), `--type-post-meta` (`0.75rem`, mono), `--type-post-body` (the authored role), and `--line-post-body` (`1.65`, `1.55` below `48em`).

Below `48em`, the type roles step down instead of each component overriding sizes: `--type-page-title` is `1.75rem`, `--type-section-title` is `1.15rem`, and `--type-card-title` is `0.98rem`. Components must not add their own mobile font-size clamps for these roles.

Page headers (`PageHeader`: members, notices, courses, settings) use page-header roles: `--type-page-intro` (`0.9375rem`, `--text-sm` below `48em`) for the intro, `--page-header-gap` (`16px`, `12px` below `48em`) between eyebrow, title, intro, and actions, and `--page-header-block-start` / `--page-header-block-end` (`40px` / `16px`, `0` / `8px` below `48em`) for the header's block padding, so on phones the shell's own top padding is the only space above the eyebrow. The profile identity card keeps its avatar beside the name on phones with a `64px` avatar instead of stacking.

## Spacing and sizing

Spacing scale: `4`, `8`, `12`, `16`, `20`, `24`, `32`, `40`, `48`, `64`, `80`, `96`, `128`, and `160px`. Semantic layout roles define fluid page gutters (`24–64px`), `48px` section rhythm, card inset (`16–24px`), shell clearance (`--shell-clearance`, `24px`: the gap between the header and page content), navigation offset (`--navigation-offset`, `12px`), and navigation height (`--navigation-height`, `56px` at every size). Below `48em`, page gutters become `16px`, section rhythm becomes `40px`, card inset becomes `16px`, and shell clearance becomes `16px`. Controls are `40px` tall (`--control-height`; `32px` small, `48px` large); touch targets remain at least `44px`.

`Surface` is one frame at every size. Do not nest a framed surface inside another on mobile. Post cards, discussion rows, and the composer follow [Journal](#journal).

Below `48em` the adaptive dialog is a full-screen sheet (`100dvh`) with a sticky `--navigation-height` title bar (glass, hairline bottom rule, close button). The post composer fills the sheet as described in [Journal](#journal); its legend is `--type-fieldset-legend` (`--text-md` below `48em`).

Page-level grid containers that hold content columns declare `grid-template-columns: minmax(0, 1fr)`. An implicit `auto` column grows to its widest child's min-content, which widens the page beyond the viewport and makes mobile browsers zoom the whole page out.

Content widths:

- Feed and reading column: `min(100% - 32px, 760px)`
- Wide application shell: `1280px`
- Lumen shell columns: app rail `--size-app-rail` (`14.5rem`), lesson rail `--size-lesson-rail` (`17rem`), tutor context panel `--size-context-panel` (`18rem`), lesson reference panel (the right rail) `--size-reference-panel` (`19.5rem`, `--size-reference-panel-min` `16rem` between `62em` and `75em`), and the tutor conversation column `--width-conversation` (`48rem`)
- Standard modal: approximately `640px`
- Reading/composition modal: approximately `760px`

Course covers use `--aspect-course-cover` (`2 / 1`) in library cards and on the course page, and the library grid fills columns no narrower than `--width-course-card-min` (`17rem`). A course without a cover shows the first letter of its title on a muted panel. The feed's course post shows the same cover treatment beside a mono eyebrow, the display-role title, level, and a three-line summary on a bezel panel; below `48em` the cover stacks above the copy. An unavailable course is a muted note. No new tokens were added.

The **course page** (Lumen Batch 5, 2026-10-16) opens with a muted `--text-xs` Back to courses link (leading arrow), then the Lumen page header on a hairline bottom rule: badges (the level as an accent `LabelChip`, and Draft or Archived), the `h1` at `--type-page-title` in Inter bold, the summary as a muted intro at `--type-page-intro` (at most `60ch`), a `MetadataRow` with line icons (owner, lesson count), the intended learner (a semibold `--text-xs` label over muted `--text-sm` text), and the viewer's course progress as a labelled `ProgressMeter` (at most `28rem`), shown once the course has published lessons. Manage course is a secondary button in the header's tools slot on the right; a course cover sits under it (`--aspect-course-cover`, `12rem`–`22rem` wide, hairline, `--radius-lg`, cropped to fill); a course without a cover shows none there. ## Motion

Durations are `140ms` for press feedback, `180ms` for ordinary transitions, `320ms` for overlays, and `820ms` for one-time reveals. All use `--ease-physical: cubic-bezier(0.32, 0.72, 0, 1)`. Animation is limited to transform and opacity; entrance effects must use `IntersectionObserver`, must not replay during feed refreshes, and become effectively instant under `prefers-reduced-motion`. Continuous parallax and layout-property animation are prohibited.

## Responsive behavior

Wordinator targets desktop learners first (see [what it is](what_is_it.md#desktop-first)). New work is composed for desktop (roughly `1280px` and wider, with `62em`–`75em` as the narrowest layouts it must not break), and every UI decision also specifies its phone equivalent below `48em`, shipped in the same change (owner decision, 2026-10-16). Phone support is not being discontinued. The [AI tutor](ai-tutor.md#entry-point) (C14) is designed and tested at phone and desktop widths alike.

Use Mantine-aligned breakpoints near `36em`, `48em`, `62em`, and `75em`; components should respond to available space rather than device names.

- Desktop: the left navigation rail, centered feed, modal composer
- Below `68rem`: slim header with the navigation drawer
- Phone layout: no journal hero, compact page headers, one frame per surface, and full-screen composer, reading wizard, and lesson player
- Avoid horizontal scrolling for authored content

## Component character

- **Cards** (`Surface`): one paper card (`--color-core`, line border, `--radius-lg`, `--shadow-card`). Tones: `quiet` and `inset` on `--color-surface` without shadow, `featured` on the dark feature roles (`--color-feature-*`, which stay dark in both schemes), `danger` on `--color-danger-surface`.
- **Buttons** (`Button`): `--radius-sm`, `--control-height`, `--type-control-label` semibold, a `1px` lift on hover and no press shadow. `primary` on the accent (hover `--color-hover`), `secondary` on the control surface with a `--color-separator` edge that darkens on hover, `quiet` transparent with the soft accent on hover, `danger` on the danger tint. An optional trailing glyph renders through Mantine's right section, outside the label (which clips overflow so long labels end in an ellipsis); pass icons only through `trailingIcon`, never as children or `rightSection`.
- **Icon buttons** (`IconButton`): square `--control-height`, `--radius-sm`. `default` on the control surface with a line border whose edge turns accent and the glyph `--color-action-soft-text` on hover; `quiet` transparent, soft accent on hover, for actions inside rows, cards, and headers; `primary` on the accent (such as the tutor's Send). Do not restyle an icon button's surface locally.
- **Button groups** (`ButtonGroup`, a labelled `role="group"`): members attach at `--radius-sm` with line seams; the group does not lift, members gain a `--color-wash` on hover. Horizontal only. Below `40em` members share the width by label length and wrap a long label onto two lines (never mid-word).
- **Switchers** (Mantine `SegmentedControl`, styled globally in `index.css`): a paper track with a line border; the active option sits on `--color-inverse-surface` with `--color-inverse-text`.
- **Inputs**: paper with a line border at `--radius-md`; focus turns the border accent with a `--focus-ring-width` ring in `--color-action-soft`. No floating labels.
- **Badges** (`LabelChip`): pill, `--type-badge` medium DM Mono on a soft tint (D3, restored in Lumen Batch 6). Tones: `default` (muted), `accent`, `success`, `warm`, `info`.
- **Eyebrows** (`Eyebrow`): accent, `--type-eyebrow`, bold, uppercase, `--tracking-eyebrow`.
- **Avatars** (`Avatar`): round, `--size-avatar` by default. Tones: `ink` (default, initials on `--color-inverse-surface`), `accent` (the tutor), `soft` (initials in `--color-action-soft-text` on `--color-action-soft`).
- **Metadata** (`MetadataRow`, `MetadataItem`): faint `--type-metadata` DM Mono with tabular figures (D3, restored in Lumen Batch 6); each item may lead with a `1rem` line icon.
- **Progress** (`ProgressMeter`): a `--size-progress` track on `--color-hairline` with an accent fill (success when complete); `showLabel` adds a label and percentage row above. Dark panels set `--progress-track` and `--progress-label`.
- **Page and section headers**: `PageHeader` is the eyebrow, a `--type-page-title` title at `--tracking-display`, the intro, and a tools slot on the right. `SectionHeader` is a `--type-section-title` heading with an optional short description and a trailing action.
- **Callouts** (`Callout`): the variant's lesson tint with a line border in the variant's ink, a round icon tile filled with that ink, and the variant name as an eyebrow (hidden from screen readers, which hear it as the label).
- **Dialogs**: one paper panel at `--radius-lg` with `--shadow-overlay` over a plain overlay (no blur).
- **Tooltips**: on ink, `--text-xs` semibold.
- **Icons**: Lucide line icons at a `1.5` stroke (set globally), `1rem` small and `1.25rem` medium; shared inline icons match.
- Empty and error states: plain-language copy and one obvious recovery action.
- Reactions: line chips that expose count and identities, with hover and the selected state on `--color-action-soft` ([Journal](#journal)). Do not color dislike as a destructive system error.

## Reusable component contract

The reusable UI layer owns application-wide visual or behavioral contracts: actions and icon actions, surfaces, page/reading containers, labels, eyebrows, avatars, feedback and loading states, form help, dialogs, confirmations, menus, popovers, and tooltips. Domain language, authorization, data loading, and multi-step feature workflows remain in feature components. Wrap a Mantine primitive only when Wordinator adds one of these shared contracts.

The implemented component layer provides the `default`, `quiet`, `featured`, `inset`, and `danger` surface tones; normal and reading density; button variants with an optional trailing glyph; attached button groups; shared wrappers for text, password, textarea, select, checkbox, and radio controls; page and section headers; split layouts; metadata rows and items; badges and eyebrows; toned avatars; navigation items; standard, adaptive, and confirmation dialogs; and reveal/stagger utilities. Feature pages migrate onto these contracts in their redesign batches rather than creating page-local equivalents.

Every applicable shared component defines default, hover, keyboard-focus, pressed or selected, disabled, loading, and error behavior. Semantic HTML or Mantine supplies keyboard behavior and accessible names; styling must not remove them. Focus is one `--focus-ring-width` accent outline at `--focus-ring-offset`, controls are at least `--control-height` (`40px`), and foreground/background pairs use the documented ink-based contrast. Authored text and safe links wrap without forcing horizontal page overflow. Motion uses the central duration scale and becomes effectively instant under `prefers-reduced-motion`.

The production-safe `/ui` route is the canonical visual inventory. It uses only static fixtures and i18next-backed copy, displays real exported components rather than visual copies, and follows the Lumen reference sheet: a hero with the eyebrow, title, intro, and the rotated ink mark; **01 Foundations** (six swatches: ink, canvas, paper, accent, soft blue, soft lime; display, heading, body, and label specimens); **02 Controls** (buttons, fields and progress, status and identity); **03 Product patterns** (a course card, a reference item, and conversation turns assembled from the exported components); **04** the dual-theme previews; and **05 Inventory** (forms, surfaces, overlays, feedback). Its dual-theme foundation includes the real preference control plus deterministic light and dark scopes rendering actual navigation, surfaces, action variants, validation, disabled/loading states, authored content, and feedback components regardless of the active application scheme.

The dual-theme gate (Chromium and WebKit) verifies startup resolution, explicit persistence, live system changes, document and browser-chrome propagation, representative production routes at `390px` and `1440px`, overlays, deterministic previews, overflow, semantic contrast, forced colors, reduced motion, and unfiltered media; the motion audit inspects first-party stylesheets only because Mantine and BlockNote ship their own easing. Pixel baselines were removed with the Lumen redesign (2026-10-16, decision D8 in [REDESIGN_PLAN.md](../REDESIGN_PLAN.md)); visual matching is checked manually.
